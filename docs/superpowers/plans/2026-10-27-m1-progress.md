## How the code differs from the plan

The review rounds changed the plan's code. The plan stays as originally written; the
changes, all in the commits above:

- `okf::pystr` (new): `is_py_space`, `py_strip`, `py_rstrip`, `py_lstrip`, `is_py_word`.
  Rust's `trim`/`\w`/`\s` differ from Python's: ported regexes use `[\p{L}\p{N}_]` for `\w`
  and `[\s\x1c-\x1f]` for `\s`, and no-argument strips use the pystr helpers.
- `yaml`: flow nesting limit (128), lazy block-list validation (okf.py's generator order),
  expanded divergence list.
- `workspace`: `DiskWorkspace::new` returns `Result` and canonicalizes the root; writes use
  unique `tempfile` temp files with `sync_all` + `persist`; the root is refused as a write
  target; symlinks resolving outside the root are refused for reads and writes;
  `list_markdown` returns only readable paths (skips dangling/outside symlinks).
- `paths`: `escapes_root` (exact `..` components), allocation-free `walk_order`.
- `doc`: each frontmatter line keeps its own line ending (mixed-ending files are preserved
  byte for byte); `append_seq_item` re-parses internally (no `current` parameter);
  `SeqItems` struct.
- `markdown`: no fancy-regex; `find_links` is a single-pass `regex` with a consumed
  preceding char (`(?:\A|[^!])`) emulating `(?<!!)`; underscore-emphasis removal is a linear
  scan; `re.I` patterns spell out U+0130/U+0131.
