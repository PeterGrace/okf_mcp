# M4 Task 7: `search` across catalogs, and the `tags` wording (2026-11-03T01:02:43Z)

Issue #34, Task 7 of `docs/superpowers/plans/2026-11-02-okf-mcp-m4-read-only-server.md`
(milestone 4, epic #64). Closes #34, first filed as an M2 follow-up (PR #24).

## Added

- `src/okf/search.rs`: `search_catalogs` runs `search` on each `(name, snapshot)`
  pair and merges the hits: best `SearchRank` first, then catalog order, then path, at
  most `limit`. `CatalogHit` is one merged hit, its `SearchHit` fields flattened beside
  `catalog` in the JSON. One test,
  `search_catalogs_merges_by_rank_then_catalog_order_then_path`.
- `src/mcp/search.rs`: the `search` tool, `SearchParams` (`query`, `catalogs`,
  `type`, `tags`, `status`, `limit`, default 20) and `SearchResult` (`hits`). The
  search runs on a blocking thread over each selected catalog's current snapshot. Tests:
  `tags_match_whole_tags_while_free_text_matches_substrings`,
  `search_spans_the_selected_catalogs_and_names_each_hit_s_catalog` (which also shows
  the `catalogs` argument winning over the connection's catalogs) and
  `the_schema_says_tags_match_whole_tags_only`. After review (PR #81), `limit` is capped
  at 200 (`MAX_LIMIT`; test `the_limit_defaults_to_20_and_is_capped_at_200`), and its
  description says so and that 0 returns no hits.

## Changed

- `SearchHit` derives `JsonSchema` (its skipped `rank` stays out of the schema).
- `OkfServer::tools` joins `search_router` to `catalogs_router`.
- The tool's description and its `tags` parameter's description say the `tags` filter
  matches whole tags only, while free text in `query` matches tags by substring (#34).
- The plan's Task 7 gained a dated `Corrected (issue #34)` note.
- The design's `search` row: `limit?` (default 20, at most 200).

## Notes

- schemars keeps a doc comment's line breaks in the description, so a phrase a test (or
  a reader) looks for must not be split across comment lines; the `tags` comment is
  wrapped to keep "whole tags only" together.
- Each catalog's search returns at most `limit` hits, so the merge sorts at most
  catalogs x limit items. (catalog order, path) is unique, so the unstable sort is exact.
- The blocking closure owns `Arc` handles to each catalog's state and loaded snapshot,
  taken once before the search, so every catalog is searched at one consistent version
  and no catalog name is copied until a hit is built.
