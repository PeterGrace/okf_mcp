# M5 Task 10: review of PR #114 (issue #100)

## Changed

- `store::publish::replayed_text`: a replayable entry whose path was deleted since its base revision is a `Conflict`. Replaying it onto nothing would silently re-create a file someone else deleted, or return the replay's own error instead of a `Conflict` that names the file.
- `Published::changeset`'s doc, which is also its schema description: with `published: false`, the changeset was not published and stays open.
- The design's "Publish" step 3 names the new conflict case. The plan's Task 10 Corrected note gains an "After review" bullet.

## Added

- `a_replay_onto_a_path_deleted_since_its_base_conflicts`, a pure test.
- `a_publish_creates_deletes_and_continues_a_tombstone_s_number`. It publishes a new file and an unlinked deletion: the ops are `create` and `delete`, the tombstone row is written, and the revision content is NULL. A second publish then re-creates the path at revision 3.
- `a_revision_written_meanwhile_is_a_conflict_not_a_database_error`. It inserts a conflicting `revisions` row by hand; publish answers `Conflict` and stores nothing.

## Notes

- No interface changed: `publish`, `PublishReport`, `own_changeset` and the error variants are as before.
