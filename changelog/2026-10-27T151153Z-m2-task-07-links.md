# M2 Task 7: `okf::analysis::links` (2026-10-27T15:11:53Z)

Issue #9, Task 7 of `docs/superpowers/plans/2026-10-27-okf-mcp-m2-analysis.md`. Ports
`okf.py`'s `link_analysis` (1005), `names_for` (996) and `prose_lines` (933) over the
snapshot, so `links_report` gives the same JSON as `okf.py links --json`.

## Added

- `src/okf/analysis/links.rs`:
  - `links_report(&Snapshot, mentions)`: broken links, broken anchors (fragment
    unquoted and lowercased, checked against the snapshot's anchors), relative links in
    concepts, orphans, dead ends, index drift (unlisted documents and concepts misfiled
    under `# Sections`), and unlinked mentions when `mentions` is true (`lint` passes
    `false`).
  - Report records `LinkIssue`, `IndexDrift`, `MentionHit`, `UnlinkedMention`,
    `LinksSummary`, `LinksReport`, with fields in `okf.py`'s key order, and
    `MIN_NAME_LEN`.
  - Unlinked mentions: one `RegexSet` holds every (concept, name) pattern, so each prose
    line is scanned once for all concepts; concepts are scanned in parallel with
    `rayon` (`collect` keeps concept order). `okf.py`'s lookbehind and lookahead are
    emulated with consumed neighbour characters, which is exact for an existence test.
- Tests: 7 in `analysis::links::tests`: link problems, index drift, unlinked mentions
  and the summary, mentions off, mention boundaries (including dotless `ı`), prose
  masking, and `names_for`.

## Changed

- `src/okf/analysis/mod.rs`: `pub mod links;`.
- The plan's Task 7: a dated correction note and the inline `names_for` fix.

## Notes

- **Plan correction.** `names_for` used `trim_end_matches(".md")`, which strips every
  trailing `.md` (`beta.md.md` gave `beta`); it now uses `strip_suffix`, Python's
  `[:-3]`. A test pins it. Nothing public changed, so later tasks need no edits.
- **Oracle checks.** Every test expectation was checked against `okf.py`: the report
  tests by `okf.py links --json` on the same files written to a scratch catalog, and the
  boundary, prose and names tests by its functions loaded with `importlib` under
  `python3 -I`.
- **Parity** (a throwaway ignored test, not committed): the report's JSON equals
  `okf.py links --json` on `pg_knowledge_catalog` (143 concepts, 161 unlinked
  mentions, no other problems) and on `tests/fixtures/catalog`. On the fixture it is
  byte-equal; on the real catalog it differs only by `json.dumps`' `ensure_ascii`
  escaping of non-ASCII text (`\u2082` vs `₂`), which is a serialization choice for
  Task 12, not a report difference.
- **Timing.** `links_report` with mentions on the real catalog takes 152 ms in release
  mode (set compile included), under the plan's 500 ms bound, so the two-stage matcher
  was not needed.
