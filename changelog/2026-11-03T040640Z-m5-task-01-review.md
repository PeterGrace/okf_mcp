# M5 Task 1: review of PR #106

Issue #90, PR #106 (Brooke's review).

## Changes

- `src/error.rs`: `From<sqlx::Error>` logs a retryable driver error (`40P01`,
  `40001`) with `tracing::warn!` before answering `Busy`. `Busy` drops the
  `sqlx::Error`, and as a non-internal error it was logged only at debug level, so
  Postgres' deadlock detail (the statement and the conflicting lock) was lost.
- `src/store/changesets.rs`: new test
  `the_prune_passes_by_a_changeset_get_or_create_found_and_holds`. One transaction
  takes `get_or_create`'s conflict path (the `FOR UPDATE` read of an existing
  changeset); `prune_empty`, with a cutoff past it, must return at once with 0 and
  leave it open, then discard it once that transaction ends. Removing `FOR UPDATE`
  from the read makes the test fail with `(1, Discarded)`.
- Design "Lock order": a key delete `SET NULL`s `changesets.key_id` without the
  catalog row, and forms no cycle with writes.
- Plan Task 1: the "Corrected (issue #90)" note lists these.

## Not changed

- `lock_catalog` keeps answering a catalog deleted mid-wait with `Refused`
  (`CATALOG_GONE`): the plan's Interfaces block and Task 8's tool doc rely on it.
- No index on `changesets.updated_at` yet: the open set is small.
- Ownerless changesets (deleted key): the store's `stranded` has no key filter,
  and Task 12's admin listing shows them with `key: null`.
