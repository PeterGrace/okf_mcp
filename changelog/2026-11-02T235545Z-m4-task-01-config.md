# M4 Task 1: `config`: the server's fields (2026-11-02T23:55:45Z)

Issue #65, Task 1 of `docs/superpowers/plans/2026-11-02-okf-mcp-m4-read-only-server.md`
(milestone 4, epic #64).

## Added

- `Config` gains the five settings the server reads: `listen` (`SocketAddr`, default
  `0.0.0.0:8080`), `allowed_hosts` (rmcp's `Host` allow-list, default
  `["localhost", "127.0.0.1", "::1"]`), `default_catalog` (`Option<String>`, default
  none), `poll_interval` (default `10s`) and `session_idle_timeout` (default `2h`).
  Durations are written with units (`"90s"`, `"30m"`, `"2h"`) through
  `humantime-serde`.
- Public defaults: `DEFAULT_LISTEN`, `DEFAULT_ALLOWED_HOSTS`, `DEFAULT_POLL_INTERVAL`,
  `DEFAULT_SESSION_IDLE_TIMEOUT`.
- `Config::validate`, called by `Config::load`: refuses a zero `poll_interval` (tokio's
  interval panics on zero), a zero `session_idle_timeout`, and an empty `allowed_hosts`
  (rmcp reads an empty list as "accept any `Host`"), and a blank `allowed_hosts` entry
  (`""` or whitespace; no `Host` matches it, so every request would get 403 with no hint
  why; added in review of PR #76). The error is `OkfError::Config` naming the file.
- Dependency: `humantime-serde = "1.1.1"`.
- Tests: the six `config` tests of the plan's Task 1 Step 2 (they replace the four M3
  tests, covering the same ground plus the new fields and `validate`).

## Changed

- Design, "Configuration": M4 reads every field except `time_server`, and the values
  that would break the server are refused at load.
- Plan: a dated `Corrected (issue #65)` note in Task 1 and one in Task 11 (below).

## Notes

- `time_server` waits for M7's clock check; until then it is an unknown key and ignored,
  like any other.
- Divergence from the plan: the `max_import_bytes` doc comment does not say "the import
  route also caps the request body at this size". The route arrives in Task 11, with a
  cap of the limit plus gzip slack, so Task 11 now adds that sentence. `allowed_hosts`'s
  default is built with `Vec::from(array)` rather than `.to_vec()` (a move, not a copy).
- No caller changes: `cli.rs` already goes through `Config::load`, so the subcommands
  validate the new fields too (a file with `poll_interval = "0s"` is now refused by
  `import` as well as by the future `serve`).
