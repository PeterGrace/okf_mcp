# M9 Task 1: web console foundation

Issue #216, Task 1 of `docs/superpowers/plans/2026-11-09-okf-mcp-m9-web-console.md`.

## Added

- `/api/v1`, nested inside the keyed router so `require_key` covers every API
  route, with `GET /api/v1/whoami` (`src/http/api/identity.rs`): the calling key's
  id, name, actor, access, reporting flag, reach and default catalog, never the
  key or its hash. Every API response carries `Cache-Control: no-store` and
  `X-Content-Type-Options: nosniff`; an unknown API path stays 404, not 401.
- `src/http/api/mod.rs`: `routes`, `context` and `require_admin`, and one stub
  file per later area (`keys`, `health`, `browse`, `search`, `catalogs`,
  `maintenance`, `changesets`), already merged, so Tasks 2 to 7 each fill in
  their own file.
- `src/http/api/testing.rs` (tests only): the synthetic `main` and `other`
  catalogs, keys at every level plus a `stranger` admin on `other`, `send`, and
  the `assert_matrix` / `assert_matrix_with` access-matrix assertions.
- `build.rs` embeds every file under `src/http/ui/` as `$OUT_DIR/ui_assets.rs`.
  `src/http/ui.rs` serves them under `/ui/` without a key, with a strict CSP,
  `nosniff` and `no-referrer`, plus `/ui/manifest.json` (the built pages). `/`
  redirects (303) to `/ui/`, and `/ui` (308) to `/ui/`.
- The console shell (`src/http/ui/`): Pico CSS 2.1.1 (vendored, MIT, header
  kept) under the console's own theme (Space Grotesk, Inter, JetBrains Mono),
  the sidebar, login with a pasted key, sign out, the light/dark toggle, and the
  JS core (`dom`, `api`, `store`, `toast`, `drawer`, `format`, `router`,
  `shell`) and components (`list-table`, `segments`, `confirm`). The router
  renders each navigation into its own fresh container and hides nav links whose
  page this build lacks. The key and preferences live in memory first and in
  `localStorage` second, so the console works where storage throws.
- `tests/ui_e2e`: a rustwright harness (headless Chromium from tokio tests, on a
  blocking thread) that fails a journey on any console error, and six journeys:
  admin sign-in and sign-out, a refused key, a read key without the Administer
  group, sign-in with throwing storage, a slow render never landing in a newer
  page, and the theme toggle persisting.
- `just test-ui`; `rustwright = "0.3.0"` as a dev-dependency.
- README "Web console" and route rows; `docs/operations.md` "Web console"
  (routes, headers and CSP, key storage, API reference, browser tests).

## Changed

- `src/mcp/mod.rs`, `src/mcp/maintenance/mod.rs`: the tool modules the API will
  call (`catalogs`, `changesets`, `documents`, `history`, `maintenance`,
  `reports`, `search`, and `maintenance::{reports, work}`) are `pub(crate)`.
  No MCP behaviour changes.

## Notes

- rustwright 0.3.0's `evaluate` awaits a returned promise, so the router
  journey needs no polling fallback.
- `api::context` and the harness's `wait_hidden` carry `#[allow(dead_code)]`
  until their first callers (Tasks 2 to 7) land, as `require_admin` does. The
  plan records this in dated "Corrected (issue #216)" notes.
- A throwaway probe journey confirmed that the harness fails on both a
  `console.error` and a CSP violation.
