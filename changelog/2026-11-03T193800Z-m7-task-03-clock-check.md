# M7 Task 3: the clock check and `/healthz`'s `clock` (2026-11-03T19:38:00Z)

Issue #142. The design's "Time", made real: the server measures its offset from
`time_server` over SNTP at startup and every 15 minutes, and `/healthz` shows the
last result without letting it change the status (plan Decision 7).

## Added

- `config.time_server`: optional; none means no check. A blank value is refused at
  load ("time_server is blank; name the NTP server or leave it out").
- `src/clock_check.rs`: `ClockStatus { ok, checked_at, offset_ms?, stratum? }`,
  `check_once`, and the constants `CHECK_INTERVAL` (15 minutes), `QUERY_TIMEOUT`
  (5 seconds, DNS included) and `MAX_OFFSET_MS` (2000). `check_once` logs at
  `error` past 2 seconds of offset, at `warn` on a failed query (with the error,
  which names the server), and at `debug` otherwise.
- `App::{clock_status, set_clock_status, check_clock_until}`. The loop's first
  tick is the startup check. Shutdown is raced against both the wait and the
  query itself, so a stop never waits out a 5-second query. Without a
  `time_server` it returns at once.
- `http::serve` spawns the loop beside the poll loop and awaits it after
  shutdown, logging a panic.
- Tests (7): `time_server_is_optional_and_never_blank`,
  `a_check_records_the_offset_and_stratum`, `a_failed_check_records_why`,
  `a_status_names_no_server_and_no_error`,
  `the_clock_check_runs_at_startup_and_stops_with_the_server`,
  `without_a_time_server_there_is_no_check`,
  `healthz_reports_the_last_clock_check_without_changing_its_status`. All use the
  fake server on 127.0.0.1 or a silent local socket; none queries a real server.

## Changed

- `/healthz`'s body gains `clock`: `null` without a `time_server` or before the
  first check, else `{"ok", "checked_at", "offset_ms"?, "stratum"?}`. The route is
  public, so it never carries the server's name or the error text; those go only
  to the logs. Its HTTP status still depends only on the database.
- `tests/server.rs` and `healthz_reports_an_unreachable_database_as_503` expect
  `"clock": null`.
- The config test that used `time_server` as its unknown key now has a real
  unknown key (`a_later_key`).
- Design: "Time" (the `warn` on failure, the timeout, what `clock` holds, the
  status is unaffected), the `/healthz` row, and "Configuration" (`time_server` is
  M7's and optional; a blank one is refused).
