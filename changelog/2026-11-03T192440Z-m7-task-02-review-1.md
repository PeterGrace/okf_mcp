# M7 Task 2: review 1 (2026-11-03T19:24:40Z)

Brooke's review of PR #149 (issue #141), two inline comments, both applied.

## Changed

- `src/ntp.rs`: `query` now tries every address the name resolves to, in the
  resolver's order, until one gives a usable reply, all within the one timeout. When
  every address fails it reports the last one's error (`NoAddress` when there were
  none). Before, only the first address was tried, so a dual-stack name whose first
  family has no route from the host failed with `Io`. The work is split into
  `exchange` (resolve), `ask_each` (the loop) and `ask` (one request). A silent
  address still uses up the rest of the timeout; one with no route fails at once.
- `src/ntp.rs`: `to_ntp` clamps the nanoseconds to 999_999_999. chrono reports
  10^9 ns or more inside a leap second, which would have overflowed the 32-bit
  fraction into the seconds bits. Neither the system clock nor the test clocks
  produce such an instant, so this was theoretical.
- Tests: `a_failed_address_falls_through_to_the_next` (a closed 127.0.0.1 port, then the
  fake server), `every_address_failing_gives_the_last_error` and
  `a_leap_second_instant_stays_in_its_second`; the module has 12.
- The plan's Task 2 code block follows the file again, and its correction note
  describes these changes. The public interface and `testing` are unchanged.
