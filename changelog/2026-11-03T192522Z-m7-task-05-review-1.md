  instruction changed, so the image is the same.
  - **Base images by tag, not digest.** `rust:1.99.1-slim-bookworm` and
    `debian:bookworm-slim` stay floating tags on purpose. The trade-off:
    a rebuild picks up Debian's security fixes, but two builds from the same
    `v*` tag can differ. A pushed release is fixed by its digest, so an old
    release tag should not be rebuilt; a security rebuild ships as a new
    version. Digest pinning would make rebuilds reproducible but would need a
    manual bump for every Debian fix.
  - **Cache mounts.** They only help local or long-lived builders. A GitHub
    runner starts with empty mounts (`cache-to: type=gha` exports layers,
    not mount contents), and `COPY . .` before the build means any source
    change rebuilds every crate. Acceptable for tag-only builds (about 227
    crates, a few minutes on a runner); a cargo-chef dependency layer is the
    fix if CI build time ever matters.
