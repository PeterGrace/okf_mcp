# M5 Task 8: the write path and the content write tools (2026-11-03T051920Z)

Issue #98, Task 8 of `docs/superpowers/plans/2026-11-03-okf-mcp-m5-writes.md`.

## Added

- `src/write.rs`: `apply(ctx, catalog, by, op)` and `WriteReport`. In one transaction
  it takes the catalog row, gets or creates the connection's changeset and locks it
  (`changesets::lock`), reads the overlay under that lock, runs the op on a copy of the
  overlay workspace (blocking thread), checks `rules::check_path` and `check_content`
  on every touched path, and upserts the entries (first base revision kept, else
  `Loaded::revision`; replay accumulated until a free edit; a touched path that is no
  longer a file is a deletion entry). It commits and forgets the cached overlay.
- `store::changesets::lock`: `FOR UPDATE` on a changeset row, then a fresh read
  (`None` if the row is gone).
- `src/mcp/writes.rs`: `create_concept`, `edit_document`, `replace_body`,
  `set_frontmatter` (`writes_router`), with the path forms in their schemas.
- `mcp::testing::writer` (stores the key row, then a write context).
- Tests: `lock_waits_for_the_holder_and_reads_its_commit`,
  `a_write_opens_a_changeset_and_stores_an_entry`,
  `a_read_key_is_refused_before_anything_is_stored`,
  `a_second_write_keeps_the_first_base_revision`,
  `machinery_and_secrets_are_refused_and_nothing_is_stored`,
  `by_defaults_to_the_keys_actor_and_now_comes_from_the_clock`,
  `the_overlay_shows_the_edit_to_this_key_and_label_only`,
  `a_deleted_path_is_stored_as_a_deletion_entry`,
  `concurrent_writes_to_one_changeset_lose_no_edit`,
  `replay_operations_accumulate_until_a_free_edit`,
  `the_content_tools_edit_through_the_overlay`, `edit_document_refuses_log_md`,
  `the_write_tools_have_object_output_schemas_and_say_who_by_defaults_to`.

## Changed

- `Overlays::get` takes any executor (`impl PgExecutor<'_>`) instead of `&PgPool`.
  The write path passes its transaction, so a write holding the changeset's row lock
  never needs a second pooled connection (with 8 connections and 8 queued writers, it
  could not get one).
- `apply`'s closure takes `&MemWorkspace` and `apply` takes `by` (plan Interfaces
  note, Task 8). The op runs on `with_changes(std::iter::empty())`, Task 7's copy.
- `INSTRUCTIONS` says write tools edit this connection's changeset.
- The design's "Data flow", Write.

## Notes

- The changeset row lock serializes writes to one changeset; the overlay's cached
  `version` is never used as a concurrency token. `get_or_create` already takes the
  row `FOR UPDATE`, so `lock` re-takes it and re-reads the row; publish and discard
  share it.
- A write commits its changeset even when the op touched nothing (an idempotent `log`).
  The empty changeset holds no work and the 24-hour prune closes it.
