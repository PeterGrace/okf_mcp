# M11 Task 1: migration 0009 and the UnknownName error

## Added
- `migrations/0009_users_teams.sql`: the `users`, `teams` and `team_members` tables (names `^[a-z0-9-]+$`, server-supplied timestamps, `teams.personal_of` unique per user, roles `owner`/`member`), and nullable `api_keys.user_id`, `sign_in_codes.user_id` and `catalogs.owner_team_id`, each `ON DELETE RESTRICT` with a partial index on the non-NULL side. Existing rows stay NULL ("unassigned"); the migration creates no user.
- `OkfError::UnknownName { noun, name }`: an unknown user or team. HTTP 404; kind `UnknownName`; the JSON body carries `noun` and `name`.
- Tests: `migration_0009_keeps_every_credential_and_catalog_unassigned` (replays 0001-0008 with a legacy catalog, key, grant and sign-in code, then 0009), `a_user_with_a_credential_cannot_be_deleted` (SQLSTATE 23503), `an_unknown_user_or_team_is_a_404`.

## Changed
- `migrations_create_the_schema_and_rerun_as_a_no_op` lists `team_members`, `teams` and `users`.
