# M5 Task 8, second review of PR #112 (2026-11-03T053246Z)

## Changed

- `WriteReport.touched` lists only the paths that have an entry after the write
  (written, or a deletion). A touched path that left nothing to store (gone, and never
  published) is left out.
- `set_frontmatter`'s `value` is required. A missing `value` is a parameter error, so
  forgetting it can no longer delete the key; only an explicit `null` deletes.
- The design's "Data flow", Write step 2, notes that writers queued on one changeset's
  row lock each hold a pooled connection (8 in the pool), so enough of them can leave
  reads waiting. This is accepted for now.
- Tests: `set_frontmatter_requires_value_and_only_an_explicit_null_deletes`;
  `a_gone_path_is_a_deletion_only_if_something_is_published` asserts the filtered
  `touched`.
