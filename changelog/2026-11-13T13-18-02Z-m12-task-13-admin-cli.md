# M12 Task 13: admin CLI and admin parity

## Added
- `okf-mcp user set-admin NAME --on|--off`, `set-email NAME EMAIL|--clear`, `invite NAME`, `entitle NAME CATALOG --access read|write`, `unentitle NAME CATALOG`, `sessions NAME`, `revoke-sessions NAME`, `sign-ins NAME [--limit N]`.
- `okf-mcp catalog set-member-access NAME --access none|read|write`.
- `okf-mcp settings list|set KEY VALUE|reset KEY` and `okf-mcp mail test ADDRESS|queue|retry ID|delete ID` (`src/cli/admin.rs`).
- 16 parity rows and the `user` and `catalog` command table rows in `docs/operations.md`; `tests/admin_parity.rs` covers the new subcommands and also scans the `settings` and `mail` groups.

## Changed
- `okf-mcp user list` shows `email E` and `admin yes|no` after the credential count.
- `tests/admin_parity.rs`: `every_user_and_team_subcommand_is_covered` is now `every_subcommand_of_the_scanned_groups_is_covered`.

## Notes
- Each command calls the same store function as its REST route (`users::set_admin`, `set_email`, `end_sessions`, `id_by_name`, `mail::invite::send_setup`, `ceiling::{entitle, unentitle, set_member_access}`, `user_sessions::list`, `sign_in_events::recent`, `settings::{list, set, reset}`, `mail::queue::{enqueue, list, retry, delete}`); no SQL is duplicated.
- The CLI may clear the last admin user (Decision 16): it passes `allow_last: true`; the API passes `false`.
- `user invite` and `mail test` only queue the mail through apalis on the CLI's pool; no mailer is built, so they need no mail secret, and a running server's worker sends it. The setup link is never printed, and `user sessions` prints id prefixes only.
- Settings changed from the CLI record `cli` as who changed them.
- Plan corrected: `settings set|reset` take `SettingKey` with `value_enum` (it already derives `ValueEnum` with its stored names), so the plan's `parse_setting_key` was not written.
