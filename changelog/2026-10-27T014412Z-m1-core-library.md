# M1: core library (2026-10-27T01:44:12Z)

First iteration of the OKF MCP server (spec:
`docs/superpowers/specs/2026-10-26-okf-mcp-server-design.md`). No server yet; this
milestone ports `tools/okf.py`'s document model to a Rust library, checked against
`okf.py` itself by a parity harness.

## Added

- `okf::yaml`: the YAML-subset parser and renderer (plain, single- and double-quoted
  scalars, flow and block maps and lists, comments, `|`/`>` block scalars; scalars stay
  strings). `Value::to_json` keeps source key order (`serde_json` `preserve_order`), as
  Python's dicts do. Block lists are validated lazily, in `okf.py`'s generator order.
- `okf::pystr`: Python string semantics the ports need: `is_py_space`, `is_py_word`,
  `py_strip`/`py_lstrip`/`py_rstrip`, and `universal_newlines` (Python text-mode
  newline handling, returning a `Cow` that doesn't allocate when there is no `\r`).
  Ported regexes spell out Python's `\w` as `[\p{L}\p{N}_]` and `\s` as `[\s\x1c-\x1f]`.
- `okf::doc`: `Doc`, frontmatter split into lines with textual edits (`set_block`,
  `delete_block`, `seq_items`, `append_seq_item`) that change only the edited key's
  lines; every other byte is kept.
- `okf::markdown`: frontmatter/body splits, ATX headings and GitHub anchor slugs, HTML
  anchors, footnote definitions, link finding and resolution to bundle paths.
- `okf::paths`: bundle-relative path arithmetic (`normpath`, `join`, `dirname`,
  `basename`, `escapes_root`), `is_concept`, `os.walk`-compatible `walk_order`,
  `resolve_concept` and `new_concept_path`.
- `okf::workspace`: the `Workspace` trait, `DiskWorkspace` and the in-memory
  `MemWorkspace` for tests. `Workspace::read_text` is the analysis read path (universal
  newlines, as `okf.py`'s text-mode reads); `read_to_string` stays byte-preserving for
  `Doc`.
- `clock`: the `Clock` trait, `SystemClock`, `FixedClock` for tests, `format_timestamp`.
- `error::OkfError` (`thiserror`): `NotFound`, `InvalidPath`, `FrontmatterParse`,
  `Shape`, `Io`.
- Parity harness (`tests/parity.rs`, `tests/parity/okf_shim.py`): a synthetic corpus
  under `tests/fixtures/catalog` (frontmatter, YAML error kinds, block scalars, flow
  nesting, escapes, BOM, CRLF and lone-CR files, fence variants, slug collisions,
  footnotes) and render inputs. Goldens in `tests/golden` are generated from `okf.py`
  (`UPDATE_GOLDEN=1`, one atomic regenerate test) and are self-describing: `render.json`
  stores each input with its renderings, and `SOURCE` records the SHA-256 of the `okf.py`
  they came from; a live test fails with a "goldens may be stale" message when `okf.py`
  changes. Comparisons cover values, key order (serialized text), YAML error lines and
  error kinds (the message prefix before quoted source text), headings, slugs and
  footnote definitions. `.gitattributes` marks fixtures and goldens `-text` so CRLF,
  lone-CR and BOM files stay byte-exact.

## Workspace hardening

- `DiskWorkspace::new` canonicalizes the root once and returns `Result`.
- The catalog root itself is refused as a write target.
- Symlink containment: reads and predicates canonicalize their target and refuse (or
  report `false` for) anything resolving outside the root; writes canonicalize the
  deepest existing ancestor before creating anything and refuse to replace a symlink;
  `list_markdown` never descends into symlinked directories and returns only readable
  paths (dangling and outside links are skipped with a warning).
- Writes go to a uniquely named sibling temp file (`.okf-*.tmp`), `sync_all`, then
  `persist` (rename) over the target; the temp file is removed on every failure path.
- Modes match `okf.py`'s `open(path, "w")`: an existing file keeps its permissions
  (copied with fchmod before the rename), a new file is created with 0o666 less the
  umask, and a read-only file is refused with `PermissionDenied`.

Known limits:
- Replacing by rename does not keep an existing file's owner, group, ACLs, extended
  attributes or hard links (Python rewrites in place).
- The read-only check uses `Permissions::readonly()` (no write bit set for anyone),
  which only approximates Python's real access check: a file writable by its owner but
  not by this user is replaced where Python would fail, and a file with no write bits is
  refused even for root.
- Accepted check-then-use gap: a symlink swapped in between the containment check and
  the write could win the race. This is safe only if writes and git operations are
  serialized per worktree, which is planned for M3 and not enforced here.

## Implementation notes

- `fancy-regex` was dropped. Everything uses the linear-time `regex` crate; the two
  lookaround patterns are done in explicit code: `find_links` is a single pass with a
  consumed preceding character (`(?:\A|[^!])`) emulating `(?<!!)`, and `slugify`'s
  underscore-emphasis removal is a linear scan. `re.I` patterns spell out U+0130/U+0131.
- `Doc` keeps each frontmatter line's own line ending (mixed `\n`/`\r\n` files survive an
  edit byte for byte); only inserted lines use the first line's ending. `okf.py`
  rejoins every line with the first line's ending.

## Divergences from okf.py (deliberate)

From the module docs in `src/okf/`:

- YAML (`yaml.rs`):
  - a null key parses as the string `"null"` (what `json.dumps` writes for Python's
    `None` key), so `{null: a, "null": b}` is a duplicate-key error, and `block_item` on
    a null-key map writes `- "null": a` where Python writes `- None: a`;
  - a null item in a block list renders as `null`, not `None`;
  - a `\u`/`\U` escape naming a surrogate is an error (Python accepts it), and
    `"\U00110000"` is a "bad escape" error (Python raises an uncaught `ValueError`);
  - quoted source text in error messages uses Rust `Debug` escaping, not Python `repr`;
  - flow collections nested deeper than 128 levels are an error (no stack overflow).
- Frontmatter lines (`doc.rs`):
  - only `\n` and `\r\n` end lines; Python's `splitlines` also splits on lone `\r`,
    `\x0b`, `\x0c`, `\x1c`-`\x1e`, `\x85`, U+2028 and U+2029. A lone-`\r` file therefore
    has no frontmatter here (a golden test pins this);
  - a line ending in `\r\r\n` keeps its extra `\r`, so `k:\r` is not a key line.
- Markdown (`markdown.rs`):
  - `resolve_link` decides directories lexically, where Python asks the OS about an
    unnormalized path (`/a/zz/../b`, `/infra/x.md/..` and `..` resolve differently);
  - Unicode tables differ (Python 3.14 / Unicode 16 vs the `regex` crate, about 55 code
    points), which can change a slug;
  - `headings` assumes its lines contain no `\n`.
- Paths (`paths.rs`): only bundle-relative paths are accepted (no filesystem or
  working-directory-relative paths), and escapes are exact `..` components, so `..a` is
  an ordinary name (`okf.py` uses `startswith("..")`).
- Workspace (`workspace.rs`): `list_markdown` skips dangling symlinks and symlinks
  resolving outside the root, which `os.walk` lists; plus the rename limits above.
