# M5 Task 8, review of PR #112 (2026-11-03T052725Z)

## Changed

- `write::apply` stores a gone path as a deletion entry only if it is published now or
  was at the entry's base revision. Otherwise no entry is kept, and the changeset's own
  entry for it (a file it created, then removed) is dropped with `remove_entries`. Every
  deletion entry therefore names something published, and publish (Task 10) never sees
  a delete of a path that was never published.
- `new_entry` takes the published revision and the path's replay ops (not the overlay
  and the outcome) and returns `Err(path)` when there is nothing to store.
- The `Busy` reason for a changeset closed while a write waited no longer ends in
  "; retry": `Busy`'s `Display` already adds it.
- `src/lib.rs`'s module doc is rewrapped.
- Tests: `a_deleted_path_is_stored_as_a_deletion_entry` is replaced by
  `a_gone_path_is_a_deletion_only_if_something_is_published` and
  `a_gone_published_path_keeps_its_first_base_revision`.

## Notes

- Not changed: a write that touches nothing still commits a newly opened, empty
  changeset (the review's info item). Its `WriteReport` names that changeset's id, so
  rolling it back would hand the agent an id that does not exist. The overlay over an
  empty changeset is the published state, and the 24-hour prune closes it.
