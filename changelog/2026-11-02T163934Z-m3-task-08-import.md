# M3 Task 8: `store::documents`, `store::import` and `okf-mcp import` (2026-11-02T16:39:34Z)

Issue #44, Task 8 of `docs/superpowers/plans/2026-11-02-okf-mcp-m3-storage.md`. A
catalog's files (a directory, a `.tar.gz`, or a `.tar.gz` on stdin) are loaded into
an existing catalog in one transaction under the catalog's lock.

## Added

- `src/store/documents.rs`: `DocumentRow` (a live document's path, bytes, execute
  bit, revision and `updated_at`), `published` (a catalog's live documents by path;
  Tasks 9 and 10 read it), and `Derived` (`kind`, `concept_type`, `title`, `status`,
  `tags`, derived from a snapshot document; all empty for a file the snapshot does
  not hold, such as an image or a script).
- `src/store/import.rs`: `import`, `ImportOptions { replace, actor, now }`,
  `ImportReport { added, updated, deleted, unchanged, lint }` (serializable; the CLI
  prints it as JSON).
  - Markdown that is not UTF-8 is refused (`ImportRefused`, every such path listed)
    before anything is written.
  - The snapshot and its lint are built on `tokio::task::spawn_blocking`; lint is
    reported, never refused on.
  - Into an empty catalog, every file is inserted with an `import` revision 1.
    A non-empty catalog needs `replace`; then only differences are written:
    changed content or execute bit is an `import` revision, a missing live
    document becomes a tombstone (empty content, derived columns cleared) with a
    `delete` revision (`NULL` content, message `import`), unchanged files keep
    their revision. A recreated path continues its revision numbers.
  - The catalog's `generation` is bumped only when something was written; every
    timestamp is the caller's `now`.
  - After taking the lock, the catalog is looked up again: an import that waited
    on a delete returns `CatalogNotSelected` rather than a foreign-key error.
- `okf-mcp import <catalog> <source> [--replace] [--actor A]` (`source` is a
  directory, a `.tar.gz` file, or `-` for stdin; capped by `max_import_bytes`).
- Tests: `store::documents::tests::{derived_columns_come_from_the_frontmatter,
  published_lists_live_documents_by_path}`,
  `store::import::tests::{an_import_fills_an_empty_catalog,
  a_second_import_needs_replace_and_writes_only_differences,
  a_recreated_path_continues_its_revisions_and_a_same_import_changes_nothing,
  a_changed_execute_bit_is_an_update,
  markdown_that_is_not_text_and_unknown_catalogs_are_refused,
  an_import_that_waited_for_a_delete_finds_the_catalog_gone}`,
  `cli::tests::{import_parses, import_reads_a_directory,
  import_checks_the_database_before_reading_the_source,
  import_reads_a_tarball_file_and_explains_a_missing_one}`.

## Changed

- `src/cli.rs`: `_config` is now `config` (`import` reads `max_import_bytes`). The
  source is read on a blocking thread (`read_source`), after connecting, so a
  missing or unreachable database fails before a large source is read (review of
  PR #56).
- `src/store/catalogs.rs`: the test module is `pub(crate)` and
  `until_a_lock_is_awaited` is shared with the import tests.
- Design "Import" step 3: dropped files are deleted "with `delete` revisions whose
  message is `import`".

## Notes

- Public API as planned. The plan's Task 8 has a dated "Corrected (issue #44)" note
  for the differences: lint runs in the same blocking closure as the snapshot, the
  catalog is re-checked after the lock, the row writers take one private `Write`
  struct, and the CLI reads on `spawn_blocking`. Tasks 9 to 13 use only the planned
  names and need no change.
- Rows are still written one at a time inside the transaction (the plan's decision);
  Task 13's smoke test records the real catalog's import time.
