# M11 Task 7: REST API for users, teams and assignment

## Added
- `src/http/api/people.rs`: `GET|POST /api/v1/users`, `GET|DELETE /api/v1/users/{name}`, `GET|POST /api/v1/teams`, `GET|DELETE /api/v1/teams/{name}`, `PUT|DELETE /api/v1/teams/{name}/members/{user}` and `GET /api/v1/unassigned`, over `store::users`, `store::teams` and `store::unassigned`. Creates answer 201, deletes 204; a membership change answers `{change: "added"|"role_changed"|"unchanged", team}`, a removal the team.
- `GET /api/v1/users/{name}` answers `{user, keys, codes}`, where `keys` and `codes` are only the credentials naming the user that the caller manages (the keys area's rule), so a scoped admin sees nothing outside its reach.
- `PUT /api/v1/keys/{id}/user` (keys and grants, live or revoked) and `PUT /api/v1/oauth/codes/{id}/user`, with body `{user}`, scoped like the other routes on that credential (an unmanaged one is a 404). The key route reloads the key cache before answering.
- `PUT /api/v1/catalogs/{catalog}/owner`, with body `{team}`, answering `{name, previous, owner_team}`.
- `testing::every_catalog_admin`: an all-catalogs admin key for API tests (moved from `catalogs.rs`' tests).
- Tests: eight in `http::api::people::tests`, including the access rules for every route against each fixture key, the cache-reload test and the detail filtering; `oauth::tests::an_absent_actor_is_the_name_and_a_code_is_reassigned`; new rows in the keys, codes and catalogs access matrices.

## Changed
- `POST /api/v1/oauth/codes`: `actor` is optional; absent or blank means the code's name, as for keys.
- `require_every_catalog` and `settle` moved to `src/http/api/mod.rs` (`pub(crate)`), shared by catalogs, keys and people. The Forbidden reason now reads "this needs an admin key that reaches every catalog".
- `keys::manages`, `keys::AssignUserBody` and `SignInCodeView::new` are `pub(crate)`.

## Notes
- Access follows plan Decision 3: user, team and membership writes, `set-owner` and `/unassigned` need an admin reaching every catalog; reading users and teams needs any admin.
- The code assign route does not poll: codes are read from the database on every use and `codes::assign_user` bumps no generation.
- The plan's Task 7 tests used the scoped `keys.admin` for routes that need every catalog; the plan now records the shipped tests and the fixture.
- `docs/operations.md`'s REST tables are left to Task 9.
