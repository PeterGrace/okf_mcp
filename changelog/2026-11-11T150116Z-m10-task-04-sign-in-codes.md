# M10 Task 4: Sign-in codes

## Added
- The sign-in code store (`store::oauth::codes`): `create`, `list`,
  `find_live`, `revoke`, `redeem` and `expiry` (24 hours by default, at most
  `oauth.code_max_expiry`). Only a code's SHA-256 is stored; `create`
  returns the `okfsc_` code once. `redeem` locks the code row, re-checks it,
  creates the `kind = 'oauth'` grant row, copies the code's catalogs, marks
  the code redeemed and bumps the admin generation, all in one transaction,
  so two racing redeems of one code make one grant.
- `okf-mcp oauth code create|list|revoke` and `okf-mcp oauth grant list|revoke`.
- `GET` and `POST /api/v1/oauth/codes` and `DELETE /api/v1/oauth/codes/{id}`,
  for admins within their reach; only the create response holds the code.
- Reference rows for the subcommands and endpoints in `docs/operations.md`
  ("First run", "OAuth sign-in codes") and a line in `README.md`.

## Changed
- `store::keys::resolve_grants` holds the grant and default checks shared
  by key and code creation; `is_valid_name` is `pub(crate)`.
- `api::keys` shares `manages_grants`, `requested_grants` and `parse_access`
  with the codes area. The 403 for `all` from a scoped admin now reads "may
  grant every catalog".
- Enabling maintenance reporting on an OAuth grant is a 409, not a 500
  from the `api_keys_oauth_caps` check.
- `okf-mcp key revoke|grant|ungrant|maintenance-report` resolve API keys
  only (`kind = 'key'`), by id and by name. A grant may share a key's name
  and actor, since the live name/actor index covers keys only; a key
  command never matches, acts on, or is made ambiguous by a grant. Grants
  are revoked by exact id (`okf-mcp oauth grant revoke`, `/api/v1/keys`).

## Notes
- A grant is named `<code name>.<client host>-<8 characters of the code
  id>`, because `@` is outside the key name charset.
- The CLI takes `--catalogs a,b` or `--all`, like `key create`, and requires
  `--actor`.
- Codes are never cached, so minting and revoking need no poll.
- `redeem` has no name-collision path: migration 0008's live name/actor
  index excludes grants, so the plan's unique-violation branch was dropped.
