# M5 Task 4: second review of PR #109 (2026-11-03T043755Z)

Follow-up to `changelog/2026-11-03T043055Z-m5-task-04-review.md`, after brooke-reviews' second review.

## Added

- `okf::ops::content::keeps_frontmatter`: `edit_document` and `replace_body` refuse a result
  whose frontmatter differs from the original's (presence or any line). On a document
  without frontmatter (an `index.md` too) the refusal is okf.py's "has no frontmatter; add
  it with your editor first". Before this, text written into such a document could become
  a `---` block and forge `generated`, `verified` or `reviewed`.
- `okf::ops::content::check_listing`: `create_concept` checks the listing's index and
  `index_section` (on the existing index, or on the text `ensure_index` will write) before
  writing anything.
- Test `edit_and_replace_body_refuse_to_add_frontmatter` (15 tests in `okf::ops::content`).

## Changed

- `create_concept_lists_it_under_the_named_section` now asserts that a missing section, a new
  folder without the section and a missing root `index.md` leave nothing written.
- Plan Task 4 (Corrected note, code synced) and the design's "Write tools" rows.

## Notes

- `non_blank` still returns the title unstripped: okf.py's `cmd_index` lists `title` as written.
- With frontmatter present, `keeps_frontmatter`'s line check is a guard: the earlier checks
  already keep edits out of the frontmatter.
