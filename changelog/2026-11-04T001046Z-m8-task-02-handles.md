# M8 Task 2: changeset handles and `open_changeset` (2026-11-04T00:10:46Z)

Issue #161, Task 2 of `docs/superpowers/plans/2026-11-03-okf-mcp-m8-changeset-handles.md`
(milestone 8, epic #159).

## Added

- `migrations/0003_changeset_handles.sql`: `changesets.handle`, text, `NOT NULL`,
  default `gen_random_uuid()::text`, unique (`changesets_handle_key`). The volatile
  default gives each existing changeset its own handle.
- `changesets::open` (a new, open, empty changeset whose `label` is its handle, so the
  one-open-per-label index never refuses it) and `changesets::by_handle`.
- `OkfError::UnknownChangeset { changeset }`: kind `UnknownChangeset`, not internal,
  JSON field `changeset`, HTTP 404. One message for a handle that does not exist, is
  another key's, or is in a catalog the key does not reach.
- `mcp::context::Pinned` and `ToolContext::changeset(handle, access)`. The checks run in
  this order: reach and ownership (or `admin`), then `require(access, ..)`, then the open
  state. A closed changeset is `Refused`, naming the handle and its state, with the hint
  that an empty changeset is discarded after 24 hours.
- The `open_changeset` tool (`catalog`, default: the connection's write target; write
  access). It returns `{changeset, catalog}`.

## Changed

- `ChangesetRow` gains `handle`; every query that selects a changeset returns it.
- `AppError::status`: `UnknownChangeset` is 404.

## Notes

- Labels still work: the write path, `publish`, `discard`, `revert`, `pending_changes`
  and the reads are unchanged until Task 3. A handle is not yet accepted by any tool
  but `open_changeset`.
- The plan is corrected in its Task 2 (the HTTP status mapping, the overlay test's
  `ChangesetRow` literal, the store test fixture's real name).
