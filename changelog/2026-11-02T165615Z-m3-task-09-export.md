# M3 Task 9: `store::export` and `okf-mcp export` (2026-11-02T16:56:15Z)

Issue #45, Task 9 of `docs/superpowers/plans/2026-11-02-okf-mcp-m3-storage.md`. A
catalog's live documents are written as a `.tar.gz` (design "Export"): no top-level
directory, modes 0644/0755, each entry's mtime its document's `updated_at`, no
tombstones.

## Added

- `src/store/export.rs`: `export(pool, catalog, out) -> Result<W, OkfError>` with
  `W: Write + Send + 'static`. M4's export route will call it with `Vec::new()`.
  - The catalog lookup and the document read share one read-only
    `REPEATABLE READ` transaction, so both see one snapshot (taken by the first
    query): a catalog deleted concurrently is either unknown (deleted first) or
    exported whole as it was, never empty or half-deleted. The transaction ends
    before compressing, freeing its connection.
  - `archive::write_tarball` (gzip) runs on `tokio::task::spawn_blocking`.
- `okf-mcp export <catalog> <output>` (`output` is a file, or `-` for stdout). The
  archive is built in memory first, so no `StdoutLock` is held across `.await` and
  an unknown catalog leaves no file behind; the bytes are then written on a
  blocking thread. A file is written to a temp file in its directory (mode 0666
  minus the umask), synced and renamed into place, so a failed write leaves no
  truncated archive; an existing file is replaced.
- Tests: `store::export::tests::{an_export_holds_the_live_documents_exactly,
  an_empty_catalog_exports_an_empty_archive_and_unknown_ones_fail}`,
  `cli::tests::{export_parses,
  export_writes_a_tarball_file_and_none_for_an_unknown_catalog}`.

## Changed

- The plan's Task 9 carries a `Corrected (issue #45)` note: the `Send + 'static`
  bound, the shared transaction, the CLI building in memory for files too, and the
  atomic file write.
- `okf::workspace::new_file_permissions` is `pub(crate)`, for the CLI's temp file.
  Tasks 12 and 13 call `export::export(&pool, name, Vec::new())`, which is
  unchanged.

## Notes

- The whole catalog is in memory twice at most (the rows, then the compressed
  archive), the same order as import; streaming can come with M4 if a catalog
  outgrows that.
