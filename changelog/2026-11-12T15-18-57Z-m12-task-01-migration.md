# M12 Task 1: migration 0010, sign-in errors, apalis setup

## Added
- Migration 0010: email, admin flag, password and lockout columns on `users`;
  `user_identities`, `user_passkeys`, `user_sessions`, `email_tokens`,
  `sign_in_events`, `user_catalogs`, `server_settings`;
  `catalogs.member_access`; `api_keys.self_issued` and `expires_at`
  (CHECKs `api_keys_self_issued_caps` and `api_keys_self_issued_user`);
  `key_catalogs.access` (CHECK `key_catalogs_access_level`).
- `OkfError::Unauthenticated` (401), `Gone` (410), `LimitExceeded` (422, names its limit).
- Dependencies for the milestone: apalis, apalis-postgres, argon2, async-trait,
  lettre, openidconnect, webauthn-rs (+ proto), webauthn-authenticator-rs (dev).

## Changed
- `db::migrate` (and so `okf-mcp migrate` and every CLI command) also sets
  up apalis' `apalis` schema, with its own history in
  `apalis._sqlx_migrations`. A setup error maps to `Migrate` (or
  `Database`/`Busy` for a driver error).
- The test template in `tests/support/pg.rs` runs apalis' migrations after
  okf's, and its name hashes both, so every migrated test database has the
  `apalis` schema.
- The justfile exports `SQLX_OFFLINE=true`.

## Notes
- The migration only adds; existing rows keep their meaning
  (`member_access = 'write'`, `self_issued = false`, NULL levels).
- The schema-list test orders with `COLLATE "C"`.
- Checked on Postgres 17: a non-superuser database owner runs
  `okf-mcp migrate` (citext, hstore and pgcrypto are trusted extensions), and
  a second run is a no-op.
- The plan's dependency versions and features built together unchanged; the
  plan is corrected where test databases get apalis' schema (the template,
  not `test_db()`) and where `apalis_error` lists every variant instead of a
  catch-all.
