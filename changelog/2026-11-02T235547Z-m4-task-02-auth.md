# M4 Task 2: `auth`: principals, the key cache and the bearer middleware (2026-11-02T23:55:47Z)

Issue #66, Task 2 of `docs/superpowers/plans/2026-11-02-okf-mcp-m4-read-only-server.md`
(milestone 4, epic #64).

## Added

- `src/auth.rs`:
  - `Reach` (every catalog, or a named set) and `Principal` (key id, access, reach,
    default catalog, actor; never the key itself), built from a `KeyRecord` with
    `From`.
  - `Principal::reaches` and `Principal::require`, which checks reach before access:
    a catalog the key does not reach is `CatalogNotSelected` (worded like an unknown
    catalog, so a key cannot probe which catalogs exist), and a reachable one the
    key's level does not allow is `Forbidden`.
  - `KeyCache`: every live key's principal by SHA-256 in a `HashMap`, built from
    `store::keys::list`'s records with revoked keys and malformed hashes left out.
  - `Keys`: the shared cache behind a `std::sync::RwLock<Arc<KeyCache>>`, with
    `load` and `reload` (reload swaps a whole new cache in; on a database error the
    old one stays).
  - `bearer`: the token of `Authorization: Bearer <token>`, with the scheme matched
    case-insensitively (RFC 6750) and the token trimmed.
  - `require_key`: axum middleware (`from_fn_with_state`) that inserts the
    `Arc<Principal>` into the request's extensions, or answers 401 with
    `WWW-Authenticate: Bearer` for a missing, malformed, unknown or revoked key. It
    logs the key id at debug level, never the key.
  - Five tests: `bearer_reads_the_token_with_any_scheme_case`,
    `the_cache_finds_live_keys_only`, `require_checks_reach_before_access`,
    `the_middleware_admits_a_known_key_and_refuses_the_rest` (through `oneshot`, no
    socket; unknown, revoked, `Basic` and missing keys all get 401 with the challenge) and `keys_load_from_the_database_and_reload_after_a_revoke` (Postgres).
- `OkfError::Forbidden { reason }`.
- Dependencies: `axum` 0.8.9; dev `tower` 0.5.3 (`util`, for `ServiceExt::oneshot`).

## Changed

- `src/lib.rs`: `pub mod auth;` and the crate doc's module list.
- Plan, Task 2: a dated `Corrected (issue #66)` note on the extended tests.
- Design, "Configuration": incoming keys are hashed and looked up by hash rather than
  compared in constant time (the plan's recorded deviation: a lookup's timing reveals
  only how a guess's hash compares with stored hashes, which does not help find a
  key, and a constant-time scan would cost O(keys) per request).

## Notes

- The implementation shipped as the plan wrote it (apart from `rustfmt`'s layout).
  The claims audit found three promises no test checked, so three of the five tests
  were extended: a malformed stored hash is left out of the cache; the middleware
  refuses a revoked key and a `Basic` header and always sends `WWW-Authenticate:
  Bearer` with its 401; a failed `reload` keeps the old cache. The plan carries a
  dated `Corrected (issue #66)` note in Task 2. No public symbol changed, so Tasks 3
  to 11 are unaffected.
- `keys::matches` (constant-time comparison against one stored hash) and the `subtle`
  dependency stay for callers that compare a single hash.
