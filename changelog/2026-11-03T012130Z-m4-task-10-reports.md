# M4 Task 10: the reports (2026-11-03T01:21:30Z)

Issue #73, Task 10 of `docs/superpowers/plans/2026-11-02-okf-mcp-m4-read-only-server.md`
(milestone 4, epic #64).

## Added

- `src/mcp/reports.rs`: five tools, each on one catalog (`catalog`, else the first
  selected; Decision 1) and on a blocking thread (`mcp::blocking`):
  - `open_questions` (`CatalogParam` -> `OpenQuestions`): every concept's queued
    `open_questions`, numbered from 1, in `oldest`'s order (stalest first). It reuses
    `oldest` with `open_questions_only` rather than adding an analysis.
  - `oldest` (`OldestParams` -> `Oldest`): `okf.py oldest --json`'s rows under `rows`
    (`n` defaults to 5).
  - `sprawl` (`SprawlParams` -> `Sprawl`): `okf.py sprawl --json`'s reports under
    `reports`, for one `path` or the worst `n` (default 5); an unknown path is
    `NotFound`, a non-concept `InvalidPath`.
  - `links_report` (`LinksParams` -> `Links`): `okf.py links --json` with `catalog`
    beside its keys (`serde(flatten)`); `mentions` defaults to true.
  - `lint` (`CatalogParam` -> `Lint`): `okf.py lint --json` on the published catalog with
    its commit times (`Loaded::lint`), `catalog` beside `errors` and `warnings`.
  Five tests: four on the plain functions, and one (added after review, PR #85) that
  calls the `#[tool]` methods with a request, so an ungranted `catalog` comes back as a
  `CatalogNotSelected` error result and `sprawl` on a non-concept as `InvalidPath`.

## Changed

- `src/okf/analysis/{mod,lint,links,oldest,sprawl}.rs`: every serialized report type

  `LinksSummary`, `LinksReport`, `OldestRow`, `SprawlSection`, `VolatileItem`,
  `SprawlReport`) derives `schemars::JsonSchema`. No JSON changes; live parity still
  passes 6/6.
- `src/mcp/mod.rs`: `mod reports;` and `+ Self::reports_router()` in `OkfServer::tools`.
- The plan: a dated `Corrected (issue #73)` note in Task 10 (test helper, extra
  asserts and a fifth test; no API change).

## Notes

- Every tool spells its return type `Result<Json<T>, CallToolResult>`, and the lists are
  wrapped in objects, so each is listed with an object output schema;
  `every_report_tool_is_listed_with_an_object_output_schema` checks all five.
- `lint` runs on the published catalog only; linting a changeset's pending state
  (`pending`) arrives with changesets in M5.
- `ctx.app().clock()` is a `&dyn Clock` (a trait object), so `.now()` resolves without
  importing the `Clock` trait.
