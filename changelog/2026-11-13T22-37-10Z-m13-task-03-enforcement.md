# M13 Task 3: enforcement in `Principal` and the key cache; export left open (issue #365)

## Added
- `auth::Suspensions`, the map of suspended catalogs (catalog name to owner team and notice), and `Principal.suspended`, an `Arc` of it shared by every principal of one key-cache load.
- `Principal::suspension(catalog)`, `Principal::check_not_suspended(catalog)` (refuses with `Suspended` unless the principal is an admin) and `Principal::require_export(catalog)` (read access, suspended or not).
- `KeyCache` loads the map with its other three loads (`teams::suspended_catalogs`, in the same `try_join!`), and `Keys::suspensions()` exposes it.
- Tests:
  - `src/auth.rs`: `require_refuses_a_suspended_catalog_after_reach_and_level`, `an_admin_is_not_suspended_and_export_ignores_suspension`, `a_member_session_is_suspended_and_an_admin_session_is_not`, `the_cache_gives_every_principal_the_suspended_catalogs`.
  - Every non-test caller of `Principal::require` (and `require_maintenance_report`) is exercised against a suspended catalog by one of these tests:
    - `mcp::changesets::suspension_tests`: open, a read through a changeset, write, revert, pending, discard and publish.
    - `mcp::maintenance::work::suspension_tests`: claim, renew, read revision, submit and close.
    - `http::api::maintenance`: every route.
    - `http::api::changesets`: diff and delete.
    - `http::api::browse`: the revision route, for keys and console sessions.
    - `http::api::catalogs`: update, member access and delete.
    - `http::api::keys`: create with catalogs, grant and ungrant.
    - `http::archives`: export and import.
- Test helpers: `mcp::testing::{suspend_catalogs, lift_suspension, stored_secret, cached_principal}` and `http::api::testing::{Expect, assert_answers}`.

## Changed
- `Principal::require` checks reach, then level (the old body, now the private `require_level`), then suspension. Every write, every pinned changeset, the maintenance tools and the REST routes that check access themselves now refuse a suspended team's catalog to non-admin credentials (API keys, OAuth grants and console sessions).
- `Principal::for_session` takes the suspended map; `session_principal` passes `app.keys().suspensions()`.
- `KeyCache::from_records` takes the map; `principal_of` shares it with each principal.
- Export (`/catalogs/{name}/export` and `/api/v1/catalogs/{name}/export`) uses `require_export`, so it stays open. Import stays behind `require(Admin, ..)`, so only an admin, who is exempt, imports into a suspended catalog.
- The M13 plan, Task 3: a dated correction note on the tests and helpers that shipped.

## Notes
- A credential that does not reach a catalog never learns it is suspended: reach is checked first, so it still gets `CatalogNotSelected` (404) or `UnknownChangeset`.
- The admin exemption is `access == Admin`. A ceiling never holds `admin` (`ceiling::entitle` refuses it), so a self-issued key, an OAuth grant or a non-admin session cannot reach it; only an admin-issued admin key or an admin user's session does.
- The reads that pick catalogs through `selection::resolve` or `ToolContext::offers` (browse tree, concept, links, history and document, health and reports, search, `list_changesets`) still answer for a suspended catalog. Task 4 adds the rules there.
- Review round 1 (PR #377) added the catalog delete case and the key create, grant and ungrant cases, so the coverage claim above holds for every caller. With the admin exemption removed, both of those tests fail.
- Each new path test was checked by reverting the code: with no suspension check in `require`, 8 tests fail; with no admin exemption, 9; with export through `require`, 2; without the map shared in `principal_of`, 6; and without the map passed to console sessions, the revision route's session test fails.
