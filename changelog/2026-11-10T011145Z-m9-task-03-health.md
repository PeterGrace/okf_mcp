# M9 Task 3: health dashboards

Issue #218, Task 3 of `docs/superpowers/plans/2026-11-09-okf-mcp-m9-web-console.md`.

## Added

- `GET /api/v1/catalogs/{catalog}/health` (`src/http/api/health.rs`): a
  `HealthCounts` of lint errors and warnings, sprawling concepts, orphans,
  broken links, the stalest concept's `oldest` row and the number of queued open
  questions. It runs the `lint`, `links_report` (without mentions), `oldest`
  and `open_questions` tool functions concurrently with `tokio::try_join!`.
- `GET /api/v1/catalogs/{catalog}/reports/{report}` for `lint`, `sprawl`,
  `links`, `oldest` and `questions`: the tool's result unchanged (an untagged
  `Report` enum), with `?n=` for `oldest` and `sprawl` and `?mentions=` for
  `links`.
- The Health page (`src/http/ui/js/pages/health.js`), the console's landing
  page: five tiles from the counts, a segmented switcher showing one report as a
  sortable table (fetched once per page load, until Refresh), and rows that open
  their concept in Browse through `browseHash`. Until Task 4 ships Browse, the
  router shows "Not available yet" for those links.
- API tests: counts match the reports, reports are the tool results with
  bounded row counts, bad report requests are refused, and the access matrix
  (any level reaching the catalog reads; a stranger or an unknown catalog is
  404).
- The browser journey `health_tiles_match_the_api_and_a_row_opens_its_concept`
  (`tests/ui_e2e/health.rs`).
- `docs/operations.md`, "Web console": a "Health" subsection with both routes;
  `README.md`: one sentence on the Health page.

## Changed

- `api::context` loses its `#[allow(dead_code)]`: the health handlers are its
  first callers.

## Notes

- An unknown report name is 404 `NotFound` (path `reports/<name>`), not 400:
  the name is a resource in the URL. It is checked before any report runs.
- `?n=` defaults to 20 and is clamped to 1..=200; the MCP tools default to 5.
- The sprawl count is the number of `lint`'s `sprawl` warnings, so it agrees
  with `lint` (exempt concepts are not counted), rather than running the
  `sprawl` report separately.
