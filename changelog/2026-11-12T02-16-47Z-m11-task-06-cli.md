# M11 Task 6: CLI for users, teams and assignment

## Added
- `okf-mcp user create|list|delete`. `create` also makes the personal team of the same name; `delete` refuses a user that a key, grant or code names, that belongs to another team, or whose personal team owns a catalog, and says which.
- `okf-mcp team create|list|add-member|set-role|remove-member|delete`. `add-member` defaults to `--role member`; `add-member` and `set-role` both upsert through `teams::set_member` and say whether the user was added, changed role, or already had it.
- `okf-mcp catalog set-owner NAME --team T` (prints the previous owner, `(none)` for a legacy catalog), `okf-mcp key assign ID --user U [--actor A]` (keys and OAuth grants, by id or unambiguous active name), `okf-mcp oauth code assign ID --user U`.
- `okf-mcp unassigned`: one line per legacy key, grant, sign-in code or catalog with no user or owner, or `nothing is unassigned`.
- `src/cli/people.rs` holds the new handlers. They return the text to print, so their tests compare it exactly.
- Tests: `user_create_list_and_delete`, `team_membership_round_trip`, `removing_the_last_owner_is_refused`, `catalog_create_needs_an_owner_and_set_owner_moves_it`, `set_owner_names_no_previous_owner_for_a_legacy_catalog`, `key_assign_and_unassigned`, `code_assign_gives_a_code_a_user`, `deleting_a_user_with_a_key_fails_and_says_why`, `member_changes_are_described`, `catalog_list_columns_have_the_documented_order`.

## Changed
- `key list`, `oauth grant list` (before `client X`) and `oauth code list` end with a `user U` cell (`-` when unassigned). `catalog list` prints `owner T` (`-` when unassigned) before the description.
- `oauth code create --actor` is optional; without it the grant's actor is the code's name, as for keys.
- `format_key_record` and `format_code_record` build their lines with the new `tab_row` and `labelled` helpers, which every listing now shares.
