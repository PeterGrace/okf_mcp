# M14 Task 3: Find a user by email (issue #393)

## Added

- `store::users::find_record_by_email(pool, email)`: the user whose email
  matches in any letter case, as the user list shows it (`UserRecord`), or
  `None`. Surrounding whitespace is ignored, and text that cannot be an
  address (a NUL, no `@`) answers `None` without reaching SQL.
- `GET /api/v1/users?email=`: zero or one user in the list's view, under the
  list's access rule (any admin). An unknown query parameter is 400
  (`deny_unknown_fields`), so a typo such as `?mail=` never answers the
  whole list.
- `okf-mcp user list --email ADDRESS`: prints only that user's line, and
  nothing when no user has the address.
- The Users page's filter box (`#users-filter`): narrows the loaded list,
  as you type, to users whose name, display name or email contains the
  text in any letter case. It reads nothing from the server. When nothing
  matches, the table says "No user matches the filter." rather than "No
  users yet."
- `tests/admin_parity.rs` understands flag entries (`user list --email`):
  `a_covered_flag_is_an_option_of_its_subcommand` checks the flag is an
  option of its subcommand, and the existing walk follows only the part
  before ` --` while still requiring a parity row for the whole entry.

## Changed

- `UserCommand::List` is now a struct variant, `List { email }`.
- `listTable`'s `empty` option may be a function, called at each draw.
- `docs/operations.md`: the `user list` row, a parity row for
  `user list --email`, the parity section's lead, the `GET /api/v1/users`
  API row, and a sentence on the Users page's filter box.

## Notes

- The filter lives in the table and applies to every redraw, so a list
  read that answers after the filter text changed is drawn through the
  newest filter (the journey holds such an answer). Overlapping list reads
  still draw in arrival order (#351); this task does not change that.
- Task 5 builds on this: a provisioner's lookup must give `email` and
  never sees admin users (Decision 9); `key create --provisioner` is a
  `COVERED` flag entry the new parity test checks.
