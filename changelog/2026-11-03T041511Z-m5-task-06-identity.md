# M5 Task 6: connection identity: the changeset label and the session binding (2026-11-03T041511Z)

Task 6 of `docs/superpowers/plans/2026-11-03-okf-mcp-m5-writes.md` (milestone 5), issue #95.

## Added

- `selection::{CHANGESET_HEADER, CHANGESET_QUERY, SESSION_HEADER, DEFAULT_LABEL,
  connection_label}`. A connection's changeset label (Decision 1) is the first non-blank
  `X-OKF-Changeset` header, else the first non-blank `?changeset=`, else `default`,
  trimmed. It is never the `Mcp-Session-Id`, which changes on every reconnect.
- `ToolContext::{label, with_label}`. `from_parts` reads the label from the request;
  `ToolContext::new` keeps its three arguments and uses `default`.
- `src/http/sessions.rs` (Decision 2):
  - `SessionKeys` has `new(idle)`, `bind`, `admits`, `release`, and the caller passes in
    each `Instant`, so the tests need no sleep.
  - `bind_session` is the `/mcp` middleware. A request naming a session bound to another
    key, or bound to none, gets rmcp's own `404 Not Found: Session not found`.
  - The response that issues a session binds it to the request's key, and a successful
    `DELETE /mcp` releases the binding.
  - `bind` drops bindings idle past `session_idle_timeout`, and `admits` drops an
    idled-out binding.
- `App::sessions`, built from `session_idle_timeout`.
- `mcp::testing::{principal_as, store_key, PendingEdit, pending_entry}` for Tasks 7 and
  12. `principal` now calls `principal_as("tester", Access::Read, ...)`.
- Tests:
  - `the_label_is_the_header_then_the_query_then_default_never_the_session`;
  - `the_context_takes_its_label_from_the_request`;
  - `a_connection_s_key_and_label_pick_its_changeset`;
  - the three `http::sessions` unit tests;
  - `a_session_answers_only_the_key_that_opened_it`, end to end over HTTP.

## Changed

- `http::router` has a new layer order. `/mcp` is its own router with `bind_session` as
  a `route_layer`, merged into `keyed`, so `require_key` runs first and
  `bind_session` can read the `Principal`.
- Design changes:
  - the "Decisions" Auth row says a session answers only its key;
  - the "Process and routes" `/mcp` row and the middleware paragraph describe the
    binding;
  - the "Binding it to a key" open question is removed, since it is now done.
- Plan:
  - a dated Corrected note in Task 6 (the code shipped as written);
  - the File map now credits `app_at` to Task 7, not Task 6.

## Notes

- An unbound session id gets 404 as well. Every session rmcp issues passes through the
  middleware and is bound, so an unbound id has idled out or never existed. Refusing it
  means pruning a binding can never let a second key in.
- Session ids are never logged: holding one lets you use the session.
- The T6 -> T7 dependency is already in the plan's "Task dependencies", because
  `ToolContext::view` reads `label()`.
