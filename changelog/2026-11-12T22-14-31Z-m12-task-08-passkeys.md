# M12 Task 8: passkeys

## Added
- Passkey registration from the setup link (`/auth/passkey/setup/*`) and from a signed-in console session (`/api/v1/me/passkeys/register/*`), and discoverable sign-in (`/auth/passkey/signin/*`). The open routes exist only when `public_url`'s host is a domain.
- `store::passkeys` (add, add_in, add_from_session, for_user, find, lock_for_sign_in, update_in, list, rename, remove) and `store::sign_in_methods::count`.
- `user_sessions::hold_live`, `console_session::start_session_in`, and `signin::{start_in, finish_sign_in}`: a session inserted inside the transaction that checked the credential.
- The sign-in and setup pages' passkey buttons (`js/signin/passkey.js`, with the `js/signin/webauthn.js` conversions and `createCredential` for the account page).
- `Ui::virtual_authenticator` in the browser test harness (a Chromium virtual authenticator over DevTools), and a journey that registers a passkey from a setup link and signs in with it.

## Changed
- `user_sessions::start` takes an executor, so it can run inside a caller's transaction.
- `signin::cross_site` is shared with the passkey routes; `fail_on`, `allow` and `wait_for_lock_waiters` moved to `http::api::testing`.
- `tungstenite` 0.29 is a dev-dependency (already in the tree through rustwright).

## Notes
- A passkey sign-in locks the user `FOR SHARE`, then the passkey `FOR UPDATE`, verifies the assertion, stores the counter and inserts the session in one transaction. So the counter never goes back, and no removal or password reset can commit between the check and the insert. A counter that did not move (`CredentialPossibleCompromise`) is logged at `warn` and recorded as a failed sign-in.
- The setup link is used, the passkey stored and the session started in one transaction; a failure leaves the link usable.
- Adding a passkey from a session ends the user's other sessions unless `keep_sessions` is set, in the same transaction. A session a reset ended meanwhile cannot add one.
- Ceremony state is in memory, five minutes, single use, keyed by the `okf_passkey` cookie (`SameSite=Strict`). The open routes refuse another site's requests (`Sec-Fetch-Site`); the two starts and the sign-in finish take the per-address sign-in limit.
- Passkeys are off when `public_url`'s host is an address (WebAuthn needs a domain).
