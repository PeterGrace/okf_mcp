# Milestone 9: the web console (epic #215)

A browser console at `/ui/` and the JSON API it runs on at `/api/v1`, both
on the server's existing port. Sign-in is by pasting an API key, and the
console acts with exactly that key's access. Every console action is a
documented `/api/v1` call, and each API handler calls the same tool or store
function as MCP or the CLI, so their behaviour cannot drift. The MCP tool API
is unchanged. Design: `docs/superpowers/specs/2026-11-09-okf-webui-design.md`;
plan: `docs/superpowers/plans/2026-11-09-okf-mcp-m9-web-console.md`.

## Added

- **Task 1, foundation (#216, PR #224):** the `/api/v1` router with
  `GET /whoami`, `require_key` and `no-store`/`nosniff` on every response;
  `/ui/` assets embedded by `build.rs`, with the CSP and security headers,
  and a page manifest; `/` redirects to `/ui/`; the app shell, login,
  sign-out and theme; the JS core (`api`, `router`, `store`, `dom`, `drawer`,
  `toast`, list table, segments, confirm); the access-matrix helper
  (`api::testing::assert_matrix`) and the rustwright browser harness;
  `just test-ui`.
- **Task 2, API keys (#217, PR #226):** six key endpoints and the API keys
  page: list, create (secret shown once), revoke, grant, ungrant and the
  maintenance-report flag, all within the caller's reach. Exact-id store
  mutations (`*_by_id`) so a legacy key id never reaches another key.
- **Task 3, health (#218, PR #225):** `GET /catalogs/{catalog}/health` and
  `/reports/{report}`, and the Health landing page with five tiles and the
  report switcher.
- **Task 4, browse and search (#219, PR #227):** `src/render.rs` (markdown to
  escaped HTML with scheme-restricted links and console routes), six browse
  endpoints and `GET /search`, and the Browse (tree, concept, links,
  history, revision diff, raw) and Search pages.
- **Task 5, catalogs and import/export (#220, PR #228):** catalog create,
  describe and delete endpoints, the archive routes mounted under `/api/v1`
  through shared builders, the `only_machinery` and `expect_generation`
  import options on both paths, and the Catalogs and Import & export pages.
- **Task 6, findings and runs (#221, PR #230):** six maintenance endpoints
  including the new `counts`, a disposition filter in the store, and the
  Findings (with decisions) and Runs pages and the nav badge.
- **Task 7, changesets (#222, PR #229):** the changeset list, diff and
  discard endpoints and the Changesets page.
- **Task 8, wrap-up (#223):** a whole-console browser journey
  (`tests/ui_e2e/smoke.rs`) that visits every page as an admin with no
  console error; the spec records the plan's deviations and a "What M9
  shipped differently" section; `docs/operations.md` gains an API overview,
  the 0.12.0 upgrade note and two troubleshooting rows.

## Notes

- 31 `/api/v1` endpoints, each documented in `docs/operations.md` and covered
  by its area's access-matrix test (checked against the routes in Task 8).
- No migration and no new setting: the console needs only the new image.
- Browser journeys need Chromium. On a machine whose `chromium-browser` is a
  snap stub that cannot launch, leave `RUSTWRIGHT_CHROMIUM` unset so
  rustwright finds a Playwright Chromium.
- Follow-ups raised in reviews and left open, for the epic close-out:
  - **Link paths are not percent-decoded** (PR #227 discussion).
    `resolve_link` reads a markdown destination as a literal path, so
    `[A](a%20b.md)` looks for `a%20b.md`; the lint and links reports read it
    the same way, so the console stays consistent with them. Decoding needs
    to change all three together.
  - **The Runs page reads every page of runs** before showing the table
    (PR #230 review). Kept as designed, since runs are one per scheduled
    pass; a long-lived catalog may want paging there.
  - **Legacy-id API tests** (PR #226 audit): the store test
    `by_id_changes_never_reach_a_legacy_keys_replacement` covers all four
    by-id mutations, but the API test `a_legacy_id_changes_only_its_own_key`
    exercises only revoke, not the grant, ungrant and reporting-flag routes.
- The release (v0.12.0, `just release-prepare minor`) is a separate step of
  issue #223, after the maintainer's go-ahead.
