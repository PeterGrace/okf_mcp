# Milestone 7 (deployment) delivered (2026-11-03T21:32:06Z)

Plan: `docs/superpowers/plans/2026-11-03-okf-mcp-m7-deployment.md` (PR #138); epic
#139 and sub-issues #140-#148; PRs #149-#156 and this one. Design:
`docs/superpowers/specs/2026-10-26-okf-mcp-server-design.md`. M7 is the design's last
milestone: every milestone is now delivered.

The server runs at `https://okf-mcp.k.vsix.me`, behind bearer keys, from the image
`ghcr.io/petergrace/okf-mcp:0.7.0`, with a CloudNativePG database that is backed up
continuously and has been restored once in a drill. This entry is generic on purpose:
the repository is public, and the site's details are in the private catalog.

## What shipped

- `src/ntp.rs`: a hand-written SNTPv4 client with no new dependency (RFC 4330 offset
  and round trip, the 2036 era rule, strict reply checks, every resolved address tried
  within one 5-second timeout).
- `src/clock_check.rs` and `App::check_clock_until`: the clock check at startup and
  every 15 minutes, `error` past 2 seconds and `warn` on a failed query; `/healthz`
  gains a coarse `clock` that never changes its status; `config.time_server`.
- TLS to Postgres: sqlx's `tls-rustls-ring-webpki`, set by `PGSSLMODE=verify-full` and
  `PGSSLROOTCERT`, with `tests/tls.rs`; `db::connect` unchanged.
- The image: a two-stage `Dockerfile`, `.dockerignore`, and
  `.github/workflows/image.yml`, which pushes `<version>` and `sha-<short>` (no
  `latest`) to GHCR with the workflow's token on a `v*` tag. Version `0.7.0`.
- `docs/operations.md`: the generic operator guide (image, configuration, Postgres and
  TLS, a complete Kubernetes example, first run, health and time, upgrades, backup and
  a tested restore, troubleshooting).
- `StillLinked`'s `path` and `links[].source` gained their leading `/` (the M6
  follow-up).
- The rollout and the restore drill, done on the site (below).

## Deviations from the design

From the plan's Decisions and "Simplifications and deviations relative to the
design", all written into the design's "What M7 shipped differently":

- the manifests live only in the private Argo CD source repository; this repository
  has generic operator docs (Decision 5);
- the image is on GHCR, built by GitHub Actions on tags, not pushed to a site registry;
  the workflow runs no gates (Decision 6);
- the NTP check is a hand-written SNTPv4 client, and `/healthz` reports it without
  depending on it (Decision 7);
- TLS to Postgres is configured by the environment, not the URL (Decision 8);
- the pod listens on `[::]:8080` (Decision 9);
- `StillLinked`'s paths are `/`-prefixed; other errors' paths are not (Decision 12).

## Found while building it, and plan corrections

Every dated note in the plan (`grep -n "Corrected (issue" docs/superpowers/plans/2026-11-03-okf-mcp-m7-deployment.md`
gives 13 lines; Decision 12's #140 note repeats Task 1's):

- **#140 (Task 1):** "every path a tool returns" narrowed to "as tool results
  (`touched`, `message`) and `Conflict` write them"; the other `OkfError` variants'
  slashless paths are recorded in the task's changelog, unchanged (Brooke's review of
  PR #152).
- **#141 (Task 2):** the plan's code is the merged file; the module doc names
  `from_ntp` in plain backticks (a public doc linking a private item fails `cargo doc`
  with `-D warnings`). After Brooke's review of PR #149, every resolved address is
  tried within the one timeout and a leap second's nanoseconds are clamped; 12 tests.
- **#142 (Task 3), two notes:** an existing healthz test expects `"clock": null`; the
  config test's unknown key became `a_later_key`; module docs name the clock check.
  After Brooke's review of PR #153, a `time_server` with surrounding whitespace is
  refused at load, and `a_failed_check_records_why` became
  `a_failed_check_records_no_offset`.
- **#143 (Task 4), four notes:** the refusal test requires rustls's `UnknownIssuer`,
  which sqlx 0.9.0 reports as `sqlx::Error::Io`, not `Tls`; the binary, not the image,
  is OpenSSL-free; with a TLS backend, sqlx's default `prefer` tries TLS on every
  connection that sets no mode; a URL's `sslmode` overrides `PGSSLMODE`, so the
  rollout's TLS check confirms the database URL names none (Brooke's review of PR #150).
- **#144 (Task 5):** the Dockerfile's comment no longer says "no OpenSSL":
  `ca-certificates` pulls in Debian's `openssl` package.
- **#145 (Task 6), two notes:** the Deployment sets `OKF_MCP_CONFIG` in the environment
  instead of `--config` in `args`, so `kubectl exec`'d subcommands read the same file;
  the restore's `bootstrap.recovery` names `database` and `owner`, since CloudNativePG
  defaults both to `app` (Brooke's review of PR #154).
- **#146 (Task 7):** what the rollout did differently: the config by environment; the
  object store's secret key is the AWS-style `SECRET_ACCESS_KEY`, and an
  `ExternalSecret` failing in an early Argo CD wave held back every later wave; the
  `ObjectStore` must name the store's region, or the store answers `400 Bad Request`
  and WAL archiving fails; the Service sets no `ipFamilyPolicy`, since the cluster
  forces `RequireDualStack`; `kubectl cnpg` takes flags after the plugin's name.
- **#147 (Task 8):** no `Corrected` note. The drill followed Task 8 as #145 corrected
  it. Brooke's review of PR #156 made the documented checksum deterministic across
  catalogs (order by `catalog_id, path`, include `catalog_id`,
  `convert_to(..., 'UTF8')`), and that went into `docs/operations.md`.
- **#148 (Task 9, this task):** shipped as planned, plus one fix: the design's example
  configuration named an internal host as `time_server`; it is now
  `time.example.com`, and the rewritten "Deployment" no longer names the site's
  registry host. The old values stay in git history.
