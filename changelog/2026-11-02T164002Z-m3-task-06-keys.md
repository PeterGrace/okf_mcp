# M3 Task 6: API keys: `keys`, `store::keys` and `okf-mcp key` (2026-11-02T16:40:02Z)

Issue #42, Task 6 of `docs/superpowers/plans/2026-11-02-okf-mcp-m3-storage.md`. Keys
are generated from the OS random source, shown once, stored only as SHA-256 and
compared in constant time. Grants tie a key to catalogs, or to every catalog. Every
key change bumps `server_state.admin_generation` in the same transaction, so a running
server (M4) notices.

## Added

- `src/keys.rs`: `KEY_PREFIX` (`okf_`, so people and secret scanners recognize a
  key), `generate` (32 bytes from `getrandom::fill`, unpadded base64url, 43
  characters), `hash` (SHA-256 to `[u8; 32]`), `matches` (`subtle::ConstantTimeEq`;
  a stored value of the wrong length is `false`, not a panic).
- `src/store/keys.rs`: `Access` (`Read < Write < Admin`, a `clap::ValueEnum`, with
  `as_str`/`parse`), `Grants` (`All` or `Catalogs(&[String])`), `NewKey`,
  `KeyRecord` (never the key itself), and `create`, `list`, `revoke`, `grant`,
  `ungrant`.
  - `create` refuses a bad id (`[A-Za-z0-9._-]+`, as the schema's `CHECK`), a taken
    id, and a default that is not granted; an unknown catalog (granted or default) is
    `CatalogNotSelected`. It looks every granted name up in one query and inserts
    every grant in one statement, so its round trips do not grow with the grant
    count. A name given twice is one grant.
  - `list` returns every key by id with its grants sorted and its default catalog by
    name (`default_catalog_id` joined to `catalogs`).
  - `ungrant` clears the key's default if it was that catalog; deleting a catalog
    clears it too (`ON DELETE SET NULL`), so a re-created catalog of the same name is
    not the old default.
- `okf-mcp key create ID --access read|write|admin --catalogs a,b|--all [--default C]
  [--actor A] | list | revoke ID | grant ID CATALOG | ungrant ID CATALOG`. `create`
  prints the key alone on stdout (so `$(okf-mcp key create ...)` captures it) and a
  reminder on stderr. `list` prints `id<TAB>access<TAB>active|revoked<TAB>catalogs
  (* for all)<TAB>default C<TAB>actor`.
- Dependencies: `getrandom` 0.4.3, `base64` 0.23.1, `sha2` 0.11.1, `subtle` 2.6.1.
- Tests: `keys::tests::{keys_are_prefixed_url_safe_and_unique, hash_is_sha256,
  matches_compares_hashes}`, `store::keys::tests::{access_round_trips_its_spelling_and_orders_by_level,
  create_stores_only_the_hash_and_the_grants, bad_requests_are_refused,
  revoke_grant_and_ungrant, deleting_a_catalog_clears_it_as_a_default}`,
  `cli::tests::{key_create_needs_catalogs_or_all_but_not_both,
  key_subcommands_run_against_the_database}`.

## Changed

- The design's `api_keys` row names `default_catalog_id` (a reference to `catalogs`,
  cleared when that catalog is deleted or the key loses its grant), and its subcommand
  table says `grant`/`ungrant` refuse a key created with `--all`.
- `src/lib.rs` (`pub mod keys`), `src/store/mod.rs` (`pub mod keys`).

## Notes

- Beyond the plan: `grant` and `ungrant` refuse a key granted every catalog, since a
  per-catalog grant row would contradict `KeyRecord::catalogs` ("empty with
  `all_catalogs`") and change nothing the key reaches. The plan's Task 6 gets a dated
  "Corrected (issue #42)" note for that, the batched grant lookup and insert, and the
  extra tests. No later task calls `store::keys`, so no other task changed.
- No key appears in the source or the tests: every test key is generated at run time.
