# M12 Task 12: admin REST routes

## Added
- `PUT /api/v1/users/{name}/admin`, `PUT /users/{name}/email`, `POST /users/{name}/invite`, `PUT` and `DELETE /users/{name}/entitlements/{catalog}`, `GET` and `DELETE /users/{name}/sessions`, `DELETE /users/{name}/sessions/{id_prefix}`, `GET /users/{name}/sign-ins`.
- `GET` and `PUT /api/v1/catalogs/{catalog}/member-access`.
- `GET /api/v1/settings`, `PUT` and `DELETE /settings/{key}`; `POST /api/v1/mail/test`, `GET /mail/queue`, `POST /mail/queue/{id}/retry`, `DELETE /mail/queue/{id}`.
- `mail::invite::send_setup` (shared with Task 13's `user invite`), `store::users::{id_by_name, end_sessions}`, `store::email_tokens::issue_for_user_in`, `store::ceiling::member_access` and `config::MailProvider::as_str`.
- The API reference rows for every new route in `docs/operations.md` (66 endpoints), with a new "Settings and mail API" subsection.

## Changed
- `GET /api/v1/users/{name}` lists the user's `entitlements`.
- User, catalog and mail-job names that cannot name anything (a NUL among others) are answered as unknown before any query, in the store functions these routes use (`users::{find, set_email, set_admin}`, the `ceiling` functions, `mail::queue::{retry, delete}`), so they are a 404 instead of a 500. Part of #339: the older routes' other store functions still bind such names.
- `store::ceiling` and `store::sign_in_events::recent` resolve user names through `users::id_by_name`.

## Notes
- One route per CLI action (Decision 17). Writes need an admin reaching every catalog (an admin key with `--all`, or an admin user's console session); reads need any admin; member access goes through `ceiling::may_set_member_access`.
- The API refuses to clear the last admin user (409) for every principal; only the CLI may (Decision 16). `users::set_admin` counts the admins under their row locks, and a test races two clears of the last two admins through the API.
- The setup email is issued and queued in one transaction under the user's row lock, so a concurrent email change can never leave a working link mailed to the old address. "Sign out everywhere" locks the user's row first, so a session still being inserted is ended too.
- No answer or log line holds a session id, token, hash or email address; sessions are shown by their 12-character id prefix.
- Plan corrections are recorded in Task 12's `Corrected (issue #322)` note; Task 13's `revoke-sessions` and Task 15's `user.is_admin` were updated to match.
