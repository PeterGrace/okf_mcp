# M2 Task 5: `okf::analysis` and the secret scan (2026-10-27T13:07:01Z)

Issue #7, Task 5 of `docs/superpowers/plans/2026-10-27-okf-mcp-m2-analysis.md`. Ports
`okf.py`'s `SECRET_RULES`, `ASSIGN_RE`, `PLACEHOLDER_RE`, `_literal_secret`, `_mask` and
`scan_secrets` (`okf.py` lines 1734-1791). M2's snapshot (Task 6) runs the scan on every
file, M2's lint (Task 10) reports its findings, and M4 will call it before every write.

## Added

- `serde` 1.0.229 with `derive` (already in the lock file through `serde_json`), for the
  analysis reports' `Serialize` derives.
- `src/okf/analysis/mod.rs`: the `okf::analysis` module and `Finding`
  (`file`, `line`, `rule`, `message`, serialized in `okf.py`'s key order).
- `src/okf/analysis/secrets.rs`: `scan_secrets(path, text) -> Vec<Finding>` and
  `OKF_PY_PATH` (`tools/okf.py`, the file callers skip as `okf.py` skips itself).
  - The six token rules and `ASSIGN_RE` emulate Python's lookbehinds with a consumed
    neighbour character and a capture group, and the AWS rule's lookahead with a consumed
    `(?:[^A-Z0-9]|\z)`. `ASSIGN_RE`'s `\2?` is dropped, which changes no captured value.
  - `re.I` keywords spell `i` as `[iI\u{130}\u{131}]`; the `regex` crate already folds
    long s and the Kelvin sign as Python does.
  - A `RegexSet` over all seven patterns skips a line with no candidate in one pass; only
    the rules the set flags are run for their match.
  - The statics are `LazyLock`s, compiled once on first use.
- Tests: `secrets::tests` (9: every token rule, table order of token findings, line
  splitting on `\n` only, masking, assignments and placeholders with each `why` text,
  `re.I` keywords, Unicode lookbehind/whitespace/digit classes, several assignments per
  line, `mask`), `analysis::tests::finding_serializes_with_okf_py_key_order`, and a doc
  example on `scan_secrets`. Secret-shaped strings are built at runtime; no committed file
  holds one.
  Every file this change touches scans clean under `okf.py`'s own `scan_secrets`, so even
  the generic assignment heuristic finds nothing (two test templates were reworded to keep
  a keyword out of the `format!` string).
