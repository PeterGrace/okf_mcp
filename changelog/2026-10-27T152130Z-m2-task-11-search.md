# M2 Task 11: `okf::search` (2026-10-27T15:21:30Z)

Issue #13, Task 11 of `docs/superpowers/plans/2026-10-27-okf-mcp-m2-analysis.md`. Ranked
search within one snapshot, as the plan's decision 3 defines it. `okf.py` has no search
command, so the plan's rules and tests are the specification.

## Added

- `src/okf/search.rs`:
  - `search(&Snapshot, &SearchQuery) -> Vec<SearchHit>`: every whitespace-separated term
    must occur (case-insensitive substring) in some field. Fields, best first: title or
    alias, tag, description, body. The tier is the best field holding the whole query,
    else 4 plus the best field holding any term. Deprecated concepts sort last; ties
    break by path. Type, tag and status filters (case-insensitive; a missing status is
    `stable`) and a top-k limit.
  - `SearchQuery` (default limit 20), `SearchRank` (derived `Ord`, `deprecated` then
    `tier`; M3 merges catalogs by it), `SearchHit` (path, title, description, snippet;
    `rank` is not serialized) and `SearchFields` (a concept's lowercased fields).
  - Snippets: the first body line holding the whole query, else any term, stripped and
    cut to 160 characters (not bytes).
  - Matching runs in parallel with `rayon`; only the best `limit` hits are sorted
    (`select_nth_unstable_by` partitions around the cut first).
- Tests: 8 in `search::tests`, the plan's 4 plus split-term tiers, the multi-byte
  snippet cut, fields on concepts only, and the serialized hit.

## Changed

- `src/okf/snapshot.rs`: each concept's `SnapshotDoc` carries its `SearchFields`
  (`search_fields()`), built once at the end of `read_document`; the module doc now
  links [`crate::okf::search`].
- `src/okf/mod.rs`: `pub mod search;`.
- The plan's Task 11: a dated correction note on the private internals.

## Notes

- **Plan correction.** The public API shipped as planned. Internally a private `Field`
  enum replaces the `usize` index (no catch-all arm), each term's best field is found
  once and the phrase is searched only from there on, snippets zip the body with the
  already-lowercased body instead of lowercasing every line again, and a zero limit
  returns before matching. Tasks 12-14 use only the public API, so they need no edits.
