# M3 Task 4: `config` and the `okf-mcp` command line (2026-11-02T16:01:01Z)

Issue #40, Task 4 of `docs/superpowers/plans/2026-11-02-okf-mcp-m3-storage.md`. The
binary becomes `okf-mcp` with a `clap` command line that later tasks extend, and the
configuration file gets its first field.

## Added

- `src/cli.rs`: `Cli` (`--database-url`/`DATABASE_URL`, `--config`/`OKF_MCP_CONFIG`,
  both global; the URL's value is hidden from `--help`), `Command::{Serve, Migrate}`
  and `run(cli, clock)`. No subcommand means `serve`, which fails with "the MCP server
  arrives in milestone 4". `migrate` connects, applies the embedded migrations and
  prints `migrations applied`; a missing URL fails with "no database: set
  DATABASE_URL or pass --database-url". The private `connect` helper migrates on
  every connect, so every later database subcommand works on a fresh database.
- `src/config.rs`: `Config { max_import_bytes: ByteSize }` (default 64 MiB,
  `DEFAULT_MAX_IMPORT_BYTES`), `Config::from_toml` and `Config::load(Option<&Path>)`.
  Missing keys take their defaults and unknown keys are ignored, so one file serves
  every milestone. The config is read before any command runs, so a bad file fails
  them all.
- `OkfError::Config { path, message }`: an unreadable or invalid configuration file,
  shown as `<path>: <parser message>`.
- Tests: `config::tests::{an_empty_file_gives_the_defaults,
  sizes_take_units_or_plain_numbers_and_unknown_keys_are_ignored,
  a_bad_value_names_the_file, no_file_gives_the_defaults}` and
  `cli::tests::{no_subcommand_means_serve, migrate_applies_the_schema,
  a_missing_database_url_is_explained, serve_is_not_there_yet}`. The CLI tests build
  `Cli` directly, so a `DATABASE_URL` in the environment cannot leak in.

## Changed

- `Cargo.toml`: the `[[bin]]` is `okf-mcp` (the design's name); new dependencies
  `clap` 4.6.7 (`derive`, `env`), `anyhow` 1.0.104, `toml` 1.1, `bytesize` 2.7.0
  (`serde`).
- `src/main.rs`: a `#[tokio::main]` entry point that sets up `tracing` on stderr and
  returns `cli::run`'s `anyhow::Result`, so an error prints its chain and exits 1.
- `src/lib.rs`: `pub mod cli; pub mod config;`.
- Design, "Configuration": each milestone reads only its own fields (M3:
  `max_import_bytes`) and unknown keys are ignored. "Process and routes": every
  subcommand that touches the database applies the migrations first; `migrate` is for
  deploy hooks.
- Plan: the two-filter test commands (`cargo test --lib config cli` and the like in
  Tasks 4, 5, 6, 8 and 11) are a cargo usage error; they now pass the filters after
  `--`, with a dated "Corrected (issue #40)" note in Task 4.
