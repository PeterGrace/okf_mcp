# M4 Task 6: `http` and `okf-mcp serve` (2026-11-03T01:09:21Z)

Issue #70, Task 6 of `docs/superpowers/plans/2026-11-02-okf-mcp-m4-read-only-server.md`
(milestone 4, epic #64).

## Added

- `Cargo.toml`: `tower-http` 0.6.11 (`trace`, `timeout`); tokio's `net` and `signal`
  features; dev `rmcp` (`client`, `transport-streamable-http-client-reqwest`) and
  `reqwest` 0.13.5 (`json`).
- `src/http/mod.rs`: `router` (`/healthz` with a 120-second `REQUEST_TIMEOUT`; `/mcp`,
  rmcp's `StreamableHttpService` with the configured `allowed_hosts`, the session idle
  timeout and a child of the shutdown token, behind `require_key`; `TraceLayer` on
  everything), `serve` (the poll loop beside `axum::serve`, graceful shutdown on the
  token), `AppError` (an `OkfError` as a status and its JSON; `status()` maps each
  variant) and `/healthz` (`{"database": "ok"|"unreachable", "catalogs": <count>}`,
  200 or 503; the `SELECT 1`, pool acquire included, has a 2-second `HEALTH_TIMEOUT`,
  after which it answers 503). Four unit tests: `app_errors_have_a_status_and_the_error_json`,
  `a_request_past_the_timeout_gets_503`, `healthz_reports_an_unreachable_database_as_503`
  and `healthz_gives_up_after_its_own_deadline`.
- `src/cli.rs`: `Serve(ServeArgs)` with `--listen` (`OKF_MCP_LISTEN`), the default
  subcommand; `serve` loads the app, binds, and cancels one token on SIGINT or SIGTERM
  (`cancel_on_signal`). Tests `serve_is_the_default_and_takes_listen` and
  `serve_without_a_database_is_explained`.
- `tests/support/server.rs`: `TestServer::{start, key, client, mcp_url}`, `call`,
  `structured`, `files`, `Client`: a throwaway Postgres, imported catalogs, the real
  router on a free port and rmcp clients.
- `tests/server.rs`: five end-to-end tests (`/healthz` without a key; 401 for a missing
  or unknown key; 403 for a `Host` outside `allowed_hosts`; a revoked key fails after a
  poll; selection precedence header, key default, server default, and grants).

## Changed

- `cli::run` takes `Arc<dyn Clock>` (the server keeps it); `main.rs` passes
  `Arc::new(SystemClock)` and defaults the log filter to
  `warn,okf_mcp=info,tower_http=info`.
- The design's "Process and routes": the `/healthz` body and statuses, tracing, the
  timeout on every route but `/mcp`, the shutdown token, and the `serve` row.
- The plan: a dated `Corrected (issue #70)` note in Task 6; the `router` doc link.

## Notes

- Review of PR #83: a timed-out request gets 503 through `http::timeout_layer()`
  (Task 11 reuses it); `OkfError::is_internal` covers `Io` and `Config` too, so every
  500 is logged at error level and redacted; `cancel_on_signal` no longer shuts down
  when Ctrl-C cannot be registered; request traces are at INFO and shown by default
  (`tower_http=info`); `serve` cancels its token and awaits the poll loop on an error
  too. Two new tests: `a_request_past_the_timeout_gets_503` (paused time, tokio
  `test-util` in dev) and `filesystem_errors_are_internal_and_keep_only_their_path`.

- Step 7, by hand on a throwaway `postgres:17-alpine`: `catalog create pg` printed
  `created catalog pg`; `key create me --access read --all --default pg` succeeded;
  `serve --listen 127.0.0.1:18470` logged `serving listen=127.0.0.1:18470`;
  `curl /healthz` printed `{"database":"ok","catalogs":1}`; a bare `POST /mcp` got
  `401`, and an `initialize` with the key `200`. `kill -TERM` stopped it in 0.061 s
  (`shutting down`). A second run held an SSE `GET /mcp` stream open across SIGTERM:
  exit in 0.054 s, and the stream ended.
- No public symbol later tasks use changed (`AppError`, `REQUEST_TIMEOUT`, `router`,
  `serve`, the `TestServer` API), so Tasks 11 and 12 need no edits.
- `/mcp` has no request timeout: its `GET` is a long-lived event stream.
- Test counts on the PR head (main merged through #85, reports): 339 unit, 5
  end-to-end, 6 golden parity, 1 roundtrip, 13 doc tests. This task adds six unit tests (four in
  `http`, `cli::tests::serve_without_a_database_is_explained`,
  `error::tests::filesystem_errors_are_internal_and_keep_only_their_path`), removes
  `serve_is_not_there_yet` and renames `no_subcommand_means_serve`.
- Second review of PR #83: `/healthz` has its own 2-second deadline (`HEALTH_TIMEOUT`),
  so a saturated pool or a hung Postgres answers 503 in time for a probe instead of
  after sqlx's 30-second acquire timeout.
- The crate is Unix-only: `cancel_on_signal` uses `tokio::signal::unix` without
  `#[cfg(unix)]`, as intended.
